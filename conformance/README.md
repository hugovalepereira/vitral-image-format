# Vitral conformance suite

Test files for anyone writing a Vitral decoder or renderer in another language,
tool or plugin (SPEC §11). Each case is a small (16×16) file with the result a
conforming implementation must produce. The reference implementation passes all
of them in CI (`crates/vitral/tests/conformance.rs`).

[`manifest.json`](manifest.json) lists the cases. For each one:

| Field | Meaning |
|---|---|
| `file` | The file to decode. All end in `.vitral.png`, including the plain PNG: software identifies Vitral files by the chunk, not the name (§9). |
| `status` | What the decoder must conclude (§6): `ok`, `not-vitral`, `fallback-mismatch`, `corrupt` or `unsupported`. Only `ok` yields Vitral data; in every other case the main image is shown as a normal PNG. |
| `colour_space` | `srgb` or `display-p3` (§2.4). |
| `k`, `w` | For `ok` cases only: K (result over black) and W (result over white) as RGB PNGs. A conforming decoder recovers them **exactly**. |
| `render` | The file composited over [`backdrop.png`](backdrop.png), which is opaque (§7.1). |
| `render_transparent` | The file composited over [`backdrop-transparent.png`](backdrop-transparent.png), whose alpha fades to 0 from left to right, so the native appearance shows through (§2.3). |

## Tolerances

* **Decoding:** K and W must match exactly.
* **Rendering over the opaque backdrop:** §7.1 in integer arithmetic matches
  exactly. A renderer that uses the blend-mode stack of §7.2 (CSS, Canvas,
  design tools) may differ by up to **2** levels per channel.
* **Rendering over the transparent backdrop:** up to **1** level, since §7.1
  works in real arithmetic there.

Backdrop values are used as they are, in the image's colour space: the renders
test the arithmetic, not colour conversion. The Display P3 case's expected files
are tagged as Display P3.

## What the cases cover

* Every (K, W) combination on a grid, including inversion (W < K).
* Both ways of storing the residual (flag bit 0: differences or K and W
  directly), over a partly transparent native image.
* Display P3.
* Files whose Vitral data must be ignored: a plain PNG, a main image edited
  after encoding, a damaged chunk, a truncated residual, a payload shorter than
  its header, two chunks, an unknown version and an unknown model.

## Regenerating

The files are generated by the reference implementation. After a deliberate
change to the format:

```sh
VITRAL_WRITE_CONFORMANCE=1 cargo test -p vitral --test conformance
```

New cases are welcome, especially from other implementations that found a gap.
